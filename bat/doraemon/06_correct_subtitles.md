# 剪映日文 ASR 字幕矫正 + 翻译规范

> 先翻译同一故事的日文标题/简介并生成发布标签，再把剪映双语 `.srt` 中的日文 ASR 轨道提取出来，参考日中标题与剧情简介，保守矫正日文及断句，最后重新翻译为中文；全程复用同一个本地模型服务。
>
> **核心原则**：简介先读但不能覆盖字幕；忽略剪映自带中文；无音频时只做高置信修正；所有时间边界来自原字幕；先完成整集日文矫正，再翻译；日中严格 1:1；不确定内容保留并记录。

## 1. 工作目录与输入

每个故事的素材都放在同一个桌面目录中。例如：

```text
~/Desktop/doraemon_941/
├── 941_1_origin.srt   # 剪映导出的双语字幕，不修改
├── 941_1_jp.md        # 日文标题与剧情简介，不修改
├── 941_2_origin.srt
└── 941_2_jp.md
```

输入命名规则：

- `{故事编号}_origin.srt`：剪映导出的原始双语字幕，如 `941_1_origin.srt`
- `{故事编号}_jp.md`：同一故事的日文标题和简介，如 `941_1_jp.md`

运行目录模式时，程序处理其中所有 `*_origin.srt`。每个 SRT 必须有同名的 `_jp.md`，缺失时该文件失败，不允许跳过简介继续猜测。

## 2. 剪映双语 SRT 格式

剪映当前导出的双语 SRT 是两条轨道顺序拼接：

1. 前半段：完整日文 ASR 轨道
2. 后半段：完整剪映中文字幕轨道

两轨条数相同、每条起止时间逐一相同；进入后半轨时，时间轴会回到开头。

程序只能在以下条件全部成立时提取前半日文轨道：

- 总条数为偶数
- 前后两半条数相同
- 前后两半时间轴逐条完全一致
- 第一轨具有明确日文特征，第二轨不具有同等日文特征

任一条件不满足就停止并报错，**不得依靠单次时间回跳、个别假名或猜测强行选轨**。

剪映自带的第二轨中文只用于确认文件结构，**不得作为日文修正或新中文翻译的依据**。

## 3. 输出

输出与输入写在同一目录：

- `{故事编号}_zh.md`：前置生成的中文标题、简介、封面相对链接及发布标签
- `{故事编号}_jp_fixed.srt`：矫正并重新断句后的日文字幕
- `{故事编号}_zh_fixed.srt`：根据 `jp_fixed` 重新翻译的中文字幕
- `{故事编号}_translation_questions.md`：仅存在真正存疑内容时生成

例：

```text
941_1_origin.srt
941_1_jp.md
941_1_zh.md
941_1_jp_fixed.srt
941_1_zh_fixed.srt
941_1_translation_questions.md  # 仅有疑问时存在
```

默认不覆盖已有的 `*_jp_fixed.srt` 或 `*_zh_fixed.srt`，检测到已有字幕时会在简介翻译前拒绝处理该故事。只有显式使用 `--force` 才能成组覆盖字幕；重跑成功且没有疑问时，`--force` 会清理上次生成的存疑文件。

进入处理的故事会重新生成同名 `_zh.md`（覆盖已有中文简介）；简介是独立产物，之后字幕处理失败时仍保留。字幕文件仅在全部校验通过后成组发布，失败时保留旧字幕，不留下新字幕半成品。

## 4. 工作流程

1. **模型就绪**：整次运行启动或复用一个本地服务，所有故事处理结束后只关闭自己启动的服务
2. **简介前置**：为每个待处理故事读取 `_jp.md`，翻译标题/简介并生成发布标签，写入 `_zh.md`
3. **严格解析和选轨**：逐块解析 `origin.srt`，验证编号、时间轴、字幕非空及第 2 节双轨结构，再提取日文轨道
4. **熟悉剧情**：各字幕批次显式携带同故事的日中标题/简介，剔除图片和发布标签；日中简介正文各最多 2000 字符
5. **日文矫正**：本地模型按批纠正高置信 ASR 错误、恢复完整句子和自然断句
6. **整集校验**：确认所有原始日文 ID 恰好覆盖一次，且所有时间点来自原轨道
7. **中文翻译**：整集日文矫正完成后，再按修正后条目逐条翻译
8. **最终校验**：日中条数、编号和时间轴完全一致；中文无日文假名残留
9. **成组发布字幕**：字幕和存疑结果先在临时文件中完成，全部校验通过后再一起替换正式输出

不得一边矫正一边直接翻译同一批。中文必须以完整的 `jp_fixed` 为唯一字幕来源。

## 5. 本地模型调用

使用 `config/settings.yaml` 的 `translate` 配置，通过现有 OpenAI-compatible 本地接口调用模型：

- 默认服务：`http://localhost:8080/v1`
- 默认模型别名：`qwen3.5-9b`
- Windows 默认由现有 llama.cpp 管理器按需启动，且只关闭本次流程自己启动的服务
- 已经人工启动的服务保持运行，不由本流程关闭

简介前置与后续字幕阶段共用这个服务，不中途重启；复用的是已加载的模型，不是隐式聊天历史。标题/简介的中文译文作为显式上下文传给每个字幕批次，发布标签不进入字幕提示词。

前置步骤失败策略：

- 日文简介缺失、简介翻译或写入失败：该故事停止，继续其他故事，最终返回非零
- 仅标签生成失败：仍保存不带标签的中文简介并继续字幕处理，但最终返回非零
- 字幕处理失败：保留已完成的 `_zh.md`；不发布新字幕

之后字幕模型分成两个独立阶段：

### 5.1 日文矫正阶段

每批输入包含：

- 同故事 `_jp.md` 的标题和简介（只作背景）
- 前置生成的中文标题和简介（仅供统一译名，冲突时以日文原文为准）
- 少量只读上文
- 本批必须处理的原始 ID
- 少量可选后续 ID，用于完成跨批边界的未完句

模型只返回结构化 JSON：原始 ID 分组、修正日文和真正疑问。程序负责时间轴，不允许模型生成时间。

跨批处理规则：

- 已提交的前缀只读，不得再次修改
- 本批末尾若句子延续，可使用后续窗口中的连续 ID 完成该句
- 下一批从最后已消费 ID 之后继续，保证无重复、无遗漏
- 若在可用原始边界内无法自然完成长句，保留原切分，不得创造时间点

### 5.2 中文翻译阶段

翻译阶段读取全部修正后日文条目。每条修正日文必须恰好返回一条中文，模型不得合并、拆分或改变 ID。

模型回复解析失败、ID 缺失/重复、日文矫正覆盖不完整、中文仍有日文假名时重试一次；再次失败就终止该文件，**不得用原日文冒充中文成功输出**。

## 6. 证据优先级

判断日文字幕时按以下顺序使用证据，高级别优先：

1. `origin.srt` 第一轨的实际日文 ASR
2. 同一 `origin.srt` 的前后文
3. 同故事 `_jp.md` 中明确的人物、地点、道具和剧情信息
4. 项目记忆库中已验证的术语/人工修正案例
5. 常识或推测

简介的作用是先让模型理解故事背景和专名，**不是字幕脚本**。简介与 ASR 冲突时以 ASR 为准，不得从简介补写原字幕不存在的台词。

## 7. 日文 ASR 修正规则

`jp_fixed.srt` 的目标是纠正明确 ASR 错误并恢复自然断句，不是重新创作或润色。

- 最大限度保留原始措辞、语序和口语风格
- 没有音频可听时，只做上下文能唯一确定的高置信修正
- 明显音近误识、人物称呼、地点、道具、固定梗可在证据充分时修正
- 只是“感觉不像日语”、存在多个候选、或只能靠剧情推测时不得擅改
- 无法唯一确定时保留最保守文本，并写入存疑文件

典型明确修正示例：

- `チェイア` → `ジャイアン`
- `ノーマン` → `スネ夫`
- `浦飯屋` → `うらめしや`
- `何のゲーム` → `何の芸も`

## 8. 字幕合并与拆分

### 8.1 合并优先级

1. 日语句法：相邻条目是否组成完整句
2. 语义连贯：是否表达同一个完整意思
3. 时间连续：是否没有明显停顿或场景切换
4. 说话人一致：是否能确认是同一说话人

禁止：

- 跨明显说话人切换合并
- 跨明显场景切换或独立句子合并
- 只为让中文更自然而合并
- 说话人无法判断时，为追求完整句强行合并

独立回应、转折、强调、招呼或短感叹可保留为单条，例如 `えっ`、`なに`、`でも`、`よし`、`おい`、`ねえ`。

`よ / ね / な / わ / さ / ぞ / ぜ / けど / ので / だから` 等如果只是无独立语义的碎片，应合并到相邻实义句；承担独立语义时保留。

### 8.2 阅读速度与拆分

当单条字幕的可见字符数（不含标点、引号、空格、换行）÷ 持续时间（秒）≥ 6.5 时视为过长候选。

- 只能在 `origin.srt` 已有边界上拆分
- 不得为改善阅读速度创造新时间点
- 如果没有合理边界，优先保持语义完整，不强切
- 单条峰值偏高但不连续出现可以接受

## 9. 时间轴规则

- 只使用第一轨 `origin.srt` 的原始 ASR 边界
- 合并后的开始时间 = 第一条原始 ID 的开始时间
- 合并后的结束时间 = 最后一条原始 ID 的结束时间
- 原始 ID 必须连续，每个 ID 恰好使用一次
- 不得让模型生成、推测或调整时间
- 不得为了阅读速度、视觉美观或中文表达创造新时间点

## 10. 中文翻译规则

- 只翻译完整的 `{故事编号}_jp_fixed.srt`
- 编号、条目数量、起止时间与 `jp_fixed` 完全一致
- 中文可自然调整语序，但不得增加、遗漏或解释原文信息
- 不根据剧情脑补省略的主语、对象或因果关系
- 保留粗话、撒娇、敷衍、紧张、惊讶等人物语气
- 人物、地点、道具和固定梗在整集内保持一致
- 人名统一：ドラえもん→哆啦A梦、のび太→大雄、しずか→静香、ジャイアン→胖虎、スネ夫→小夫
- 不主动加入“（笑）”“（拟声）”等解释性括号
- 不因为中文翻译方便而反向修改 `jp_fixed`
- 中文结果不得残留日文平假名或片假名

## 11. 存疑记录

只有问题确实影响日文修正、专名、中文含义或句子结构，且现有上下文无法唯一确定时才记录。

不要记录：

- 单纯中文措辞偏好
- 完全等价的两个中文译法
- 纯风格选择
- 不影响实际含义的小差异

每条记录包含：

- 阶段（日文矫正 / 中文翻译）
- 修正后 SRT 编号
- 原始日文 ID
- raw ASR
- 当前修正日文
- 当前中文
- 不确定原因

无真正疑问时不生成存疑文件。

## 12. 最终校验

### `jp_fixed.srt`

- 编号从 1 连续递增，无重复
- 无空字幕
- 所有原始日文 ID 从 1 到末尾恰好覆盖一次
- 每组原始 ID 连续
- 所有起止时间均来自第一轨原始边界
- 时间轴无非法或反向区间
- 不存在明显应合并却独立的无意义语气词碎片

### `zh_fixed.srt`

- 条目数量与 `jp_fixed` 完全一致
- 每条编号、开始时间和结束时间与 `jp_fixed` 完全一致
- 每条日中严格 1:1
- 无空字幕
- 无日文假名残留

### 文件保护

- `origin.srt` 内容和只读属性均不修改
- `_jp.md` 不修改
- 任一字幕模型批次或最终校验失败时，不发布任何新正式字幕或存疑文件；已完成的中文简介保留
- 目录中多个输入互不阻塞：一个失败不影响其余文件继续处理

## 13. 运行方式

macOS / Linux：

```bash
./bat/doraemon/06_correct_subtitles.sh ~/Desktop/doraemon_941
./bat/doraemon/06_correct_subtitles.sh ~/Desktop/doraemon_941/941_1_origin.srt
```

Windows：

```bat
bat\doraemon\06_correct_subtitles.bat "%USERPROFILE%\Desktop\doraemon_941"
```

不传路径时读取 `logs/.last_fetched`，使用对应的桌面 `doraemon_<集号>` 目录。明确重跑并覆盖已有结果时追加 `--force`。

## 14. 禁止事项

- 不修改 `*_origin.srt`
- 不修改 `*_jp.md`
- 不采用剪映自带中文作为新译文
- 不在无音频条件下进行低置信“听写式”脑补
- 不在日文修正中添加原 ASR 没有的台词
- 不在中文翻译中反向修改日文
- 不创造时间点
- 不用日文原文填充失败的中文条目
- 不绕过 JSON、ID 覆盖、日中时间轴等程序校验
