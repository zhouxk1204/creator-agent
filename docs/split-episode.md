# 剧集自动分割器（split_episode）使用说明

把一个视频文件里包含的多个小故事（通常 2 集，极少数 3 集）自动切成独立单集。
纯视觉特征检测标题封面，**不用 OCR、不用 AI**，检测完先生成预览图给你确认，再切割。

```
input/935.mp4  →  【分割器】  →  output/935#1.mp4
                                 output/935#2.mp4
                                 output/935_split.json
```

> 当前是独立工具，不接下载流程。等检测准确率验证够了，再考虑接进下载器。

---

## 环境准备

```bash
git pull
uv sync          # 首次或更新后执行，安装 opencv / numpy
```

需要系统装有 **ffmpeg**（切割用）。Windows 上双击 bat 时会自动检测 venv，缺依赖会自己跑 `uv sync`。

## 快速开始（Windows 推荐）

双击 **`bat\doraemon\03_split_episode.bat`**：

1. 提示 `Video path:` 时，把视频文件**拖进窗口**（或粘贴完整路径）回车
2. 自动执行预览检测，打印候选列表，并用看图软件打开
   `output\preview\contact_sheet.jpg`
3. **肉眼确认拼图里每个候选都是标题封面** → 输入 `Y` 回车 → 切割
4. 候选不对 → 输入 `N`，什么都不切，调参重试

完成后自动打开 `output\` 文件夹。

其他姿势：

```bat
03_split_episode.bat C:\test\935.mp4            跳过路径输入
03_split_episode.bat C:\test\935.mp4 --copy     快速模式（见下方说明）
```

也可以直接把视频文件拖到 `03_split_episode.bat` 图标上。

## 命令行用法（mac / linux / 进阶）

```bash
# 第一步：只检测，生成预览图 + 报告，不切割
uv run python scripts/split_episode.py input/935.mp4 --preview

# 确认无误后：真正切割
uv run python scripts/split_episode.py input/935.mp4
```

控制台报告长这样：

  00:10:41.750

## 输出说明

默认输出到 `<工作目录>\output\`：

| 文件 | 内容 |
|---|---|
| `935#1.mp4` / `935#2.mp4` | 切好的单集（第 2 个标题卡起始帧为分界） |
| `935_split.json` | 检测结果（分割点、标题卡位置、置信信息） |
| `preview/candidate_XX.jpg` | 每个候选标题卡的中间帧截图 |
| `preview/contact_sheet.jpg` | 所有候选的带标注拼图，一眼确认识别对不对 |

`935_split.json` 示例：

```json
{
  "source": "935.mp4",
  "fps": 24.0,
  "duration": 1285.333,
  "episodes": [
    { "name": "935#1", "start": 0.0, "end": 642.125 },
    { "name": "935#2", "start": 642.125, "end": 1285.333 }
  ],
  "title_cards": [
    { "start": 92.125, "end": 98.083, "similarity": 0.9921, "abrupt_start": true, "abrupt_end": true },
    { "start": 642.125, "end": 648.083, "similarity": 0.995, "abrupt_start": true, "abrupt_end": true }
  ]
}
```

`abrupt_start / abrupt_end` = 标题卡边界是否是硬切。为 `false` 说明边界是淡入淡出或贴着视频头尾，此时边界精度只有 0.5s 粗粒度，**建议看一眼对应 candidate 截图确认**。

## 参数表

| 参数 | 默认 | 说明 |
|---|---|---|
| `--preview` | 关 | 只检测不切割，生成预览图 |
| `-o, --output-dir` | `output/` | 输出目录 |
| `--episodes N` | 自动 | 强制集数；候选多于需要时按质量挑 N-1 个分割点 |
| `--interval` | 0.5 | 低频扫描间隔（秒） |
| `--sim` | 0.98 | 判定"画面静止"的相邻帧相似度阈值 |
| `--min-duration` | 4.0 | 标题卡最短持续时间（秒），低于此长度的不认 |
| `--pad` | 2.0 | 精修时向候选边界两侧各扩展的秒数 |
| `--copy` | 关 | ffmpeg 流拷贝切割：快，但切口对齐关键帧（可能偏 1 秒级）；默认重编码（crf 18），逐帧精确 |

## 调参 / 故障排查

**检测到的标题卡不够（漏检）**

- 先 `--preview --sim 0.975`（放宽静止判定）
- 标题卡本身短于 4 秒：`--min-duration 3.5`

**误检太多（把静止画面当成了标题卡）**

- 提高 `--min-duration 5`
- 提高 `--sim 0.985`
- 或干脆 `--episodes 2`，让程序按质量自动挑最好的分割点

**切出来的单集开头不是正好在标题卡上**

- 默认重编码模式是逐帧精确的；如果你用了 `--copy`，偏差来自关键帧对齐，去掉 `--copy` 重跑
- 边界是淡入淡出的源（`abrupt_*: false`）只能给到 0.5s 精度

**集数超过 3 被程序拒绝切割**

- 这是保护：说明检测出了 4+ 个"标题卡"，大概率误检。先 `--preview` 看拼图，确认是不是真有那么多静止卡

**ffmpeg 报错 / 找不到**

- 确认 `ffmpeg -version` 能跑；Windows 下把 ffmpeg bin 目录加入 PATH

## 工作原理（简述）

1. 每 0.5 秒抽 1 帧，缩成 96×54 灰度签名
2. 找"长时间画面高度稳定"的区间（相邻采样相似度 ≥ 0.98，允许 ≤2 个轻微抖动点以抗 x264 呼吸效应，整段均值 ≥ 0.978，持续 ≥ 4 秒）
3. 排除黑屏 / 纯色段（亮度、方差判定）
4. 候选边界 ±2 秒逐帧扫描，取**最大不连续帧**（硬切点）作为封面的精确首帧 / 末帧
5. 分割点 = 第 2、3 个标题卡的起始帧（第 1 个卡属于第 1 集）
6. ffmpeg 按分割点切割

为什么能抗编码抖动：静止画面的相似度落在窄高带（~0.98+），而真实运动画面相似度更低且波动大；抖动以孤立单点出现，场景切换是断崖式下跌，两者可区分。

## 准确率验证要点（批量测试时记录）

- [ ] 标题卡是否**每个小故事开头**都有（如果一集内多个小故事各有标题卡，需要改分割逻辑）
- [ ] `935_split.json` 里分割点是否帧级准确（抽查切好的 `935#2.mp4` 第一帧）
- [ ] 有没有漏检（只检测到 1 张卡）或误检（静止画面被当卡）的片源——把对应 `_split.json` 留下来反馈
