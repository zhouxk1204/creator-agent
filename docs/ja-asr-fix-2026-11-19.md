## 根因与修复（识别侧）

1. **Qwen3-ASR 对长窗口静默截断**：同一 11.1s 窗口只出 13 token，拆成 5.0+6.1s 两半则
   全文出齐；13.4s 窗口只出 14 token。→ `max_chunk_sec` 6.0s，`chunk_target_*` 2.5–5.0s。
2. **没有上下文 prompt 才是截断的直接原因**：`apply_transcription_request(prompt=…)`
   传入作品/角色/道具热词后，同一 11.1s 窗口出 41 token 完整文本。→ `context_prompt` 配置
   （のび太/ドラえもん/しずか/ジャイアン/スネ夫/ママ/パパ/セワシ + どら焼き/未来ラジオ/
   ひみつ道具/のび太温泉…）。
3. **稀疏窗口**（chunk 内跨长静音）只转近侧、丢远侧 → 新增 `chunk_merge_gap_sec`（0.6s），
   chunk 内不跨更长静音。
4. **音乐/噪音段空转**：5.7s 音频生成 40s、最后只留 2 字 → `asr_max_tokens_per_sec`（
   `max_new_tokens = clamp(时长×12, 48, 1024)`）。
5. **"识别到了但只识别了开头"**：`字/语音秒 < 2.5` 的块按语音组返工（rescue pass），拼回
   ≥1.2 倍才替换，时间轴不动。实测 `わら` → `ああっ、ああっ、ああっ!ひぃぃっ!`。
6. **对齐与 ASR 抢显存**（`os error 1455 页面文件太小` → 整批退化比例分摊）：起 aligner
   子进程前释放 ASR 模型（`free_asr_before_align`），整批失败再释放+等 5s 重试一次。
7. **命令行参数 dest 错位**（`--rescue-min-cps`/`--max-tokens-per-sec` 读成了不存在的
   dest → 拿到 0）：两项功能曾静默失效，已修正。

## 根因与修复（断句 / 时间轴）

1. **零时长词造假停顿** → 词时间轴用紧凑 VAD 反向校验，词间空隙里仍有语音就不是停顿。
2. **无标点就丢弃断点**（整条 cue 跨越静音）→ 改为在停顿处切，并把切点从小浊点/长音符挪开。
3. **1–2 字词碎片 + 0.05–0.3s 闪光条** → `merge_fragments_and_fix_duration`（碎片并回上一条、
   闪光条拉到 `min_cue_sec` 0.4s）。
4. **长连续旁白硬切在音节中间**（`名付けて、乗りたおセンパラ`）→ `snap_quiet_cuts`：20ms RMS
   找 ±0.45s 内能量低谷，只有确实是低谷（≤0.7×中位数）才移动切点。修复后
   `名付けて、のび太温泉!`。
5. **对齐器把整块文本压进 0.3s（26 字 / 0.29s）** → `_MAX_CUE_CPS` 12 字/秒守卫，逐 cue 判，
   超限就整块作废、改走 speech-aware 比例分摊。
6. **包含式重叠被中点切分**（第 N 块尾词「あっち」落在第 N+1 块长 cue 44.85–49.57 内部）：
   中点切分把 4.7s 砍成 0.29s，并让后面 3.6s 语音完全没有字幕。→ 包含且文字明显更短时丢弃
   短条、保留长 cue；其余重叠仍按中点分。
7. **相邻 chunk 各识别一次同一个词**（「…久しぶりにふた」/「ふたりで映画でも…」）→
   `dedupe_cue_boundaries`：时间相接且前尾=后头（2–6 字）时裁掉前一条的重复尾巴。

## 仍然存在的问题（下一阶段）

- **chunk 边界上的识别错乱**（喊叫、重叠段）：`…パパに襲いかかっ`/`かかえろ。`、
  `…あとわし`/`いらない`、`いつ買ったんですか!`/`ですか!?これ、いっちゃったんですか!?`、
  `がんばらって、連れて来よって`、`念仏が!`（应为「念写」）、`ワタシにないしょで…待て、離せ!`。
  属识别质量问题（喊叫/音乐残留），不是断句问题。
- 剩余 3 处覆盖缺口（4.2s）：1 处唱歌/喊叫段（01:53–01:55）、2 处约 1s 的短句。
- `ぐっ…!えへ` 一条 4.9s、只有 6 字 —— 长 cue 里字太少（时间轴把静音并进了 cue）。
- 想过但没做：两侧 pad 只向非语音侧延伸（`pad = min(pad, 相邻间隙/2)`），以进一步减少
  边界重复音节。

## 走过的死路（已回退，别再试）

**pad 只往静音里扩**（让相邻 chunk 不再重叠 0.2s）：本意是消灭「…襲いかかっ」/「かかえろ。」式
重复音节，实测反而更差——那 0.2s 重叠是 ASR 的 onset/offset 上下文：

| 未被覆盖语音 | 4.2s / 3 段 | 6.5s / 3 段（新增 01:10.5–01:13.1）|

已回退（保留 0.1s pad + 字幕层 `dedupe_cue_boundaries` 去重）。回退后重跑（base11）与
base9 的 srt **逐字节相同**，说明这条管线在本样本上是确定性的，回归可比。
