### 3.2 【P0·E2】VAD 三个 pass 全部漏检柔和/渐弱台词（goodbye 丢失）

**现象**：`楽しいかったよ`(48.5–50.4)、`じゃーねー`(51.8–53.4) 完全无字幕，且**不在** UNRECOVERED_SPEECH 清单里（VAD 根本没检测到，系统对这两句完全无感知）。

**追踪**（原始音频 → VAD）：
- 人声轨 48–53s 有清晰人声能量（§3.1）。
- 对 vocals 跑 silero 阈值扫描（`C:\test\audit\` 留有脚本，`creator-asr-ja` env）：

| threshold | 44–55s 检出的语音段 |
|---|---|
| 0.50（chunking/tight） | 仅 `[43.78,44.73]`、`[54.63,55.01]` —— **48–53s 全漏** |
| 0.35（当前 recovery） | `[42.56,45.92]`、`[46.43,46.91]`、`[54.43,55.04]` —— **仍全漏** |
| **0.25** | **`[49.06,50.81]`(=楽しいかったよ)、`[51.3,51.65]`、`[51.91,52.19]`(=じゃーねー)** ✓ |
| 0.15 / 0.08 | 整段糊成 `[0.58,59.77]`（BGM 全被当语音，不可用） |

**根因**：silero 对柔和/渐弱的童声告别检出概率低，需阈值降到 ~0.25 才检出；当前 `recover_vad_threshold=0.35` 偏高。
注意 `dump_words.py:105` 注释表明补漏 pass 本就是为这个 goodbye 场景加的，但 0.35 仍不够低。

**证据影响**：2 句真实台词丢失，且诊断产物（check.txt / UNRECOVERED）**完全无法暴露**——这是最危险的一类漏检。

**聚焦窗口实测**：把 48.3–53.6s 单独喂给 ASR → 输出 `楽しかったよー♪じゃーねー♪`（**完全正确**）。
证明只要 VAD 检出、ASR 就能识别。

### 3.3 【P0·E1 关联】chunking 把 BGM 桥接成超长块

**现象**：tight VAD 把 13.09–28.41s 判成**一条 15.3s 连续语音**（中间 22–26.5s 的 BGM/弱音被桥接），
`build_chunks` 只能 `forced_split_hard` 硬切成 chunk1(12.87–21.07) + chunk2(20.87–28.634)。

**根因**：`vad_chunker._split_group`(:262-272) 对单条超长连续语音段只能按 `target_max` 硬切，无法在"无人声但只有 BGM"处断开。
vocals 轨里 BGM 残留能量足以让 silero(0.5) 一直判为语音。

**影响**：あやとり 句(26.5–29) 落到 chunk2 尾部，前面垫了 ~5s 稀疏/BGM 音频 → 诱发 §3.4 的 ASR 丢尾。

**附带观察（chunk 重叠）**：`forced_split_hard` 硬切后每块两侧各 pad 0.1s，导致相邻 chunk 重叠——
idx0/idx1 重叠 0.116s、**idx1/idx2 重叠 0.200s**、idx10/idx11 重叠 0.052s（`demo_dump_rec.json` 实测）。
即 20.87–21.07 这段被 ASR 识别了**两次**（chunk1 出`…教えてー`尾、chunk2 出`あ、いいよ。`）。
本次未产生重复字幕（`resolve_overlaps` + 词时间把它们错开），但属潜在风险：重叠区若两侧都出词，
可能在边界处挤出重复/叠字。不建议消除 pad（保起音），但需知晓此行为。

### 3.4 【P0·E1】ASR 在长/稀疏 chunk 丢弃尾部台词 + 补漏 proxy 用 chunk 跨度掩盖缺口（あやとり 丢失）

**现象**：`あやとりするひと、この指留まれー`(26.5–29.07) 完全丢失。

**追踪链**（逐步定位到第一个出错环节）：
1. **VAD**：检出了（§3.3 的 13.09–28.41 大块）。✓
2. **chunk**：あやとり 落在 chunk2(20.87–28.634) 内。✓
3. **ASR**（**第一个出错点**）：chunk2 只输出 `あ、いいよ。`，把 26.5–28.5 的あやとり 整句丢弃。
   - **实测复现**：把 chunk2 原样(20.87–28.634)喂 ASR → 仍输出 `あ、いいよ。`（复现丢弃）。
   - **对照**：把 25.0–30.5s 聚焦窗口喂 ASR → 输出 `あやとりする人この指とーまれ!`（**正确**）。
   - 根因：chunk 前段是稀疏 BGM、尾部才是清晰台词，Qwen3-ASR 倾向于只转写前段清晰语音就停（本次仅生成 6 token，远未到 1024 上限，**不是截断**）。
4. **补漏 pass**（**第二个出错点，掩盖缺口**）：`ja_worker.py:633` `covered = [(c["start"], c["end"]) for c in asr_chunks]`
   用 **chunk 跨度**当覆盖代理。chunk2 跨度 20.87–28.634 把 26.5–28.5"视为已覆盖"→ 不补。
   - 源码注释(:617-620)明确写了这个假设："every speech interval inside a transcribed chunk ends up covered
     by some cue, so chunk spans are an exact stand-in for cue spans" —— **此假设在 chunk2 上不成立**
     （chunk 成功返回文本，但远未覆盖其内部所有语音）。
5. 补漏只建了 chunk12(29.2–30.5) 抓到句尾`留まれー`，识别成`ちゅらでしゅー!`，词时间 29.26–29.58 与 recovery
   语音段(28.93–29.12 / 29.54–30.21)只重叠 0.04s → cov=0.125<0.3 → **被幻觉过滤丢弃**（dropped.txt 第3条）。
6. check.txt 正确地把 21.93–28.534 列进 `[UNRECOVERED_SPEECH]`——**系统知道漏了，但补漏没补**。

**根因（两层）**：①ASR 在长稀疏 chunk 丢尾部内容；②补漏覆盖代理用 chunk 跨度而非真实 cue 覆盖，把"chunk 成功但没识别全"的缺口永久掩盖。

### 3.5 【P0·E3】ASR 误识 + 对齐失败 + 过滤 = あつまれホイッスル 丢失

**追踪**：
1. chunk6(60.55–67.898) 末尾 ASR 出 `どーどー、集まれハイ`（词时间 65.37–65.85，是把道具名听岔+提前）。
2. chunk7(68.71–78.394) 对 67–69s 的`あつまれホイッスル` ASR 只产出 `うー。`（误识）。
3. chunk7 对齐 **INVALID_TIMING**（`repro` 类塌缩）→ 退回比例分摊。
4. `うー。` cue 落在 68.93–70.76，tight cov=0.18<0.3 → **被过滤**（dropped.txt 第1条）。
5. 65.85–67.798 进 UNRECOVERED。
- **聚焦窗口实测**：66.5–70.2s 喂 ASR → `集まれ、ハイッサー!`（基本正确，远好于`うー。`）。

**根因**：①道具名跨 chunk6/chunk7 边界被切碎误识；②chunk7 对齐失败退回比例分摊，cov 计算失真；③`うー。`被当成幻觉丢掉。
该句其实可识别，是"分段+对齐+过滤"合力弄丢的。

### 3.6 【P0·E4+E5】对齐失败 → 比例分摊逐字切碎单词 + 真实台词被过滤（87–95s 段，最严重）

**现象**：人工 5 句 `いたっ/おやつなら/どら焼き!/入って、入って!/お邪魔します!`，工具碎成
`いた、お` `やつならドラ` `えもん!入って` `て!よろしくお願いします!`，且`入って、入って!`丢失。

**追踪**：
1. chunk9(87.334–95.354, merged) ASR 文本 `いた、おやつならドラえもん!入って入って!よろしくお願いします!`
   （32字；句子骨架基本齐全，但含专名误识：`どら焼き→ドラえもん`、`お邪魔します→よろしくお願いします`，见 §3.8）。

3. 退回 **speech-aware 比例分摊**（`cue_splitter._speech_timeline` :326-383）：
   - 文本按**字符占比**摊到压缩语音时间轴（`start_at/end_at = total*off/n`，:371-374）；
   - 停顿硬边界偏移量 `off = round(n*cum[i+1]/total)`（:379）——**纯按字符比例算，不感知词边界**；
   - `split_cues:83-87` 在这些偏移处直接切字符串 → **切在词中间**（お|やつ、ドラ|えもん、入って|て）。
   - **我用手算复现了精确切点**：n=32、5 段 tight 语音、4 个 ≥0.6s 间隔 → 偏移 [4,10,17,19]，
     切出 `いた、お`(0) `やつならドラ`(4) `えもん!入って`(10) `入っ`(17) `て!よろしく…`(19)，与实际输出**逐字一致**。✓
4. `入っ`(17) 词时间 91.22–93.36，但 tight VAD 对`入って、入って`(91.9–93.07) 只检出 `[92.258,92.51]`(0.25s)
   → cov=0.13<0.3 → **被过滤**（dropped.txt 第2条）→ `入って、入って!` 丢失。

**根因（两层）**：①对齐器在快速多人语音上塌缩（aligner 能力限制，>50% 词塌缩被 repair 正当拒绝）；
②**比例分摊的停顿切分按字符比例落刀，不吸附词/标点边界**——这是把一句完整台词切成 `お|やつ`、`ドラ|えもん` 的直接原因。

### 3.7 【P1·E6+E8】对齐器在长音/弱词上留空洞或锁错 → 停顿误切

- **E6 `トラエも`/`ー、引いてよー`**（chunk3, word_timed 对齐 OK）：对齐器把`も`结束在 39.21、`ー`放到 40.89，

  → `split_cues` 在此硬切（`_word_timeline:317-321`）→ 一句`どらえもんー、聞いてよー`被切成两段，句首留下`ー、`碎片。
- **E8 `ゲームやる`**：chunk0 里`ゲーム`/`やる`是零时长 token 被 repair 扩到 0.05s 放在 9.66s（`repro_out.txt` chunk0 可见`ゲーム 9.658-9.658 ZERO/NEG DUR`），
  而人工`ゲームやる人ー!`在 10.5–11.97 → `ゲームやる`被锁早 ~1s，与`人ー!`(11.098) 断开，中间 9.758–11.098 进 UNRECOVERED。

**根因**：对齐器对长持音（`もんー`）和轻读词（`ゲームやる`）时间估计不可靠；repair 只修零时长/微重叠，

## 4. 三类问题清单

### 4.1 已证实（有直接证据）

1. **5 句完整台词丢失**（E1–E4），且 4 句聚焦窗口实测可识别回来（`asr_probe_result.json`）。
2. **补漏覆盖代理用 chunk 跨度**掩盖"chunk 成功但没识别全"的缺口（`ja_worker.py:633`，あやとり 实证）。
3. **silero 0.35 漏检柔和台词**，实测需 ~0.25；0.15 又过检糊成一片（阈值扫描实证）。
4. **比例分摊按字符比例切词**，把单词切碎（手算复现 chunk9 切点逐字一致，`cue_splitter._speech_timeline`）。
5. **对齐器在快速多人语音塌缩**（chunk9 >50% 词聚到同一时刻，repair 正当拒绝 → 4/15 退回比例分摊）。
6. **对齐器在长音/弱词留空洞或锁错 ~1s**（`もんー`、`ゲームやる`，`repro_out.txt`/词时间实证）。
7. **幻觉过滤误杀真实台词**（`うー。`、`入っ`被丢，但人工配了字幕）。
8. **review.json `speech_cov` 与过滤实际口径不一致**（`:753` 恒 tight vs `:697` recovered 用 recovery）。
9. **无系统性时间轴漂移**（median≈0）；时间误差是对齐失败/比例分摊的**局部**现象。
10. **音频提取/时长/缓存/音轨一致性全部正常**；SRT polish 无重复加余量。

### 4.2 疑似（证据充分但未 100% 闭环）

1. **BGM 残留导致 silero 桥接成长块**（§3.3）：13–28.5s 被判一条连续语音。 vocals 轨 22–26.5s 确有能量，
   但"是 BGM 残留还是真背景人声"需人工听 `demo.vocals.wav` 该段确认。倾向认为是 BGM 残留。
2. **chunk2 丢尾的确切模型机理**：已知"前段稀疏 BGM + 尾部清晰台词 → 只转前段"，但模型内部为何停在此处
   无法从外部证明（任务纪律：不猜模型内部）。只能确认现象稳定复现。
3. **`おー`/`し、`/`ちゅーっ`** 是"真实非台词声音"还是"轻微幻觉"：需人工听原片 3.5s/4.9s/85.8s 判定
   （决定该归类"噪音"还是"该过滤的幻觉"）。

### 4.3 目前无法判断（缺证据）

1. **对齐器塌缩的原始词时间**：`repair_word_timing` 返回 None 时原始词序列被丢弃（`_gate_alignment:814-818`），
   无法看到 chunk9/7/4/13 塌缩前的完整词时间。**缺诊断**：建议失败时把原始词时间写入日志/review。

## 5. 优化方案（分级；先判环节再谈改法，不盲目调模型）

> 总原则：本批错误**几乎全部来自切窗/分段/后处理层**，不是模型。优先修这些，少动模型参数。

### P0-1 修复补漏覆盖代理（chunk 跨度 → 真实 cue 覆盖）
- **现象/案例**：あやとり 丢失（E1）。
- **根因/位置**：`ja_worker.py:633` 用 chunk 跨度当覆盖。
- **方案**：覆盖代理改为"成功 chunk 的**真实语音覆盖**"——用 tight VAD 段与 chunk 内已生成文本量的比值，
  或直接用"chunk 内 tight 语音段 − 已对齐词覆盖"作为缺口。最小改法：补漏检测时，对每个成功 chunk，
  只把它**实际产出 cue 的时间范围**（而非整个 chunk 跨度）计入 covered；chunk 内未被 cue 覆盖的 tight 语音段照常进补漏。
- **副作用/回归**：可能增加补漏 chunk 数（更多小 chunk）→ ASR/对齐耗时略升；需防与已有 cue 重叠（`resolve_overlaps` 兜底已在）。
- **验证**：重跑后 あやとり 句应出现；SUMMARY `speech not subtitled` 时长下降；`chunk_recovered` 上升但 `cues_dropped` 不暴增多。
- **是否重跑模型**：需重跑 ASR/对齐（改的是检测逻辑，要重新补漏）。可先只对 26–29s 验证。

### P0-2 比例分摊切分吸附词/标点边界
- **现象/案例**：87–95s 一句碎成 4 段、词被切断（E5）。
- **根因/位置**：`cue_splitter._speech_timeline:379` 停顿偏移按字符比例落刀；`split_cues:83-87` 直接切。
- **方案**：比例分摊模式下，停顿硬切点**吸附到最近的句读（、。！？)或 allow 的软标点**（窗口 ±2~3 字内），
  无标点时退到"不切在已知长词中间"的保守位置；并在切分后**清理 cue 起始的孤立标点/单 mora**。
- **副作用**：切点可能偏离真实停顿 ±2~3 字，cue 边界时间略不准（但比例分摊本就只是估算）；碎词消失换来边界略松。
- **验证**：87–95s 不再有 `お|やつ`、`ドラ|えもん` 式断词；split 块数下降；不漏字。
- **是否重跑模型**：**不需**——可用 `demo_dump_rec.json` 里的现成 chunk 文本+tight 段**离线重切**验证（`reshape.py` 模式）。

### P0-3 找回被 silero 0.35 漏检的柔和台词（goodbye）
- **现象/案例**：楽しいかったよ/じゃーねー 丢失且诊断无感知（E2）。
- **根因/位置**：silero 检出率，`recover_vad_threshold=0.35` 偏高（实测需 ~0.25）。
- **方案（两步走，先低风险）**：
  a. **只把 `recover_vad_threshold` 降到 0.25**（不动主分块 0.5），重跑验证这两句是否进补漏。
  b. 若 0.25 在其他集引入音乐误检，则改"双阈值"：主阈值 0.35 + 对"连续 ≥1s 无主字幕的人声能量区"追加一次 0.25 检测。
- **副作用**：0.25 会把更多 BGM/呼吸当语音 → 补漏 chunk 增多、幻觉风险升（靠 speech_cov 过滤+cps 判据兜）。
- **验证**：goodbye 两句进字幕；`chunk_recovered` 增加但 `.dropped.txt` 里不出现大段音乐幻觉；其他集抽听。
- **是否重跑模型**：需重跑（VAD→补漏→ASR→对齐）。

### P0-4 幻觉过滤区分"幻觉"与"定时错误的真实台词"
- **现象/案例**：`うー。`(=ホイッスル)、`入っ`(=入って入って) 被误丢（E3/E4）。
- **根因/位置**：`ja_worker.py:717` 仅以 tight cov<0.3 判幻觉；比例分摊/对齐失败时 cov 失真。
- **方案**：对**对齐失败(比例分摊)的 chunk**，丢弃阈值更保守（如 cov<0.15 才丢），或把这类低 cov cue **标
  `SUSPECT_TIMING` 进 review 而非直接丢**（丢 = 信息永久丢失，标 = 人工可挽回）。
- **副作用**：可能多留少量真幻觉 → 靠 review 清单人工筛。
- **验证**：`.dropped.txt` 里"像正常台词"的条目减少；丢失台词数下降。
- **是否重跑模型**：**不需改模型**；改过滤/标记策略后离线重算即可（用现成 transcript+dump）。

### P1-1 降低对齐塌缩退回比例分摊的比例
- **现象/案例**：4/15 chunk INVALID_TIMING，且都集中在最难的段（E5/E6/E8 的源头之一）。
- **根因/位置**：对齐器在快速多人/长音/重叠语音塌缩；`repair_word_timing:116` >50% 修复即拒。
- **方案**：①失败时**把原始词时间写进 review/日志**（先补诊断，§4.3.1）；②评估给 aligner 喂**更小的对齐窗口**
  （把 >8s 的 merged chunk 在 VAD 子段处再切小再对齐，多人抢话段尤其）；③对长持音(`もんー`)类，可在 repair 后
  用"相邻有真实时长词线性插值"补空洞而非留洞。
- **副作用**：更小对齐窗口 → 对齐调用增多、略慢；插值补洞可能引入 ±0.2s 误差。
- **验证**：`align_fallback_INVALID_TIMING` 计数下降；E6/E8 类停顿误切消失。
- **是否重跑模型**：需重跑对齐（不动 ASR）。

### P1-2 动漫专名/同音字识别错误
- **现象/案例**：`トラエも`→どらえもん 等（E7，§3.8）。
- **根因**：ASR 模型对哆啦A梦专名覆盖有限。
- **方案**：①调研 Qwen3-ASR 是否支持 hotword/上下文提示（给了了道具名/角色名表）；②或在 ASR 后接一个
  **专名纠错词典**（ドラえもん/どら焼き/ツブワン/あつまれホイッスル…，结合 `learn` 知识库）做受控替换。
- **副作用**：词典误替换风险（需限定义+只替换高置信专名）；这是**文本层**改动，不动时间轴。
- **验证**：专名错误条数下降；不错改正常词。
- **是否重跑模型**：取决于方案（提示=重跑 ASR；后纠错=可离线）。

### P2-1 清理 cue 起始碎片 + 非台词声音
- **方案**：①cue 文本前处理：去句首孤立标点/单 mora（`し、`、`ー、`、`。`）；过滤时若整 cue 被丢，**连同其尾部标点一起清**（修 cue19 句首`。`）。
  ②非台词声音（欢呼/哨音/笑声）：用"该 cue 文本是否含实义词素"启发式或干脆对 <0.4s 且落在静音区的 cue 默认不输出（进 review）。
  ③`srt_min_display_sec` 试 0.7 拉长短 cue（改 .srt 即可，不动 transcript）。
- **是否重跑模型**：**不需**，离线后处理。

### P2-2 统一 speech_cov 诊断口径
- **方案**：`ja_worker.py:753` 的 diag `speech_cov` 改用与过滤一致的 `cov_intervals`（或同时记 tight/recovery 两个值）。
- **是否重跑模型**：**不需**，纯诊断字段。
