# 字幕问题反馈模板

核心原则：描述**现象、证据和期望**，不要直接指定改哪个参数。你不需要判断问题出在 VAD、对齐还是切分，那是 Claude Code 对着日志和代码去定位的事。你只要给它足够的证据，让它能复现并判断改对了没有。

## 每类问题要说清楚什么

| 现象 | 必须说清楚的 | 它通常会去查的环节 |
|---|---|---|
| **时间轴不对** | 字幕比语音**早还是晚**、大约多少秒、是整体偏移还是个别条、出现在哪个源时间 | 先看 `AUDIO_VIDEO_MISMATCH`，再看对齐回退原因和边界检查 |
| **字幕太长** | 具体几个字、几秒，是不是一句话里本来有停顿却没断 | `max_cue_chars`、`max_cue_sec`、`pause_sec` |
| **字幕太碎或一闪而过** | 多短、是哪类内容 | `pause_sec`、`srt_min_display_sec` |
| **识别错误** | 贴「识别结果」和「实际台词」对照，并归类：同音字、专有名词、漏字、多字 | ASR 模型、人声分离、chunk 切法 |
| **语气词太多** | 看下面单独说明 | 幻觉过滤、`repeat_tail_max_cps` |
| **漏字幕** | 源时间、那段是什么内容（对白、BGM 下、低语） | `UNRECOVERED_SPEECH`、`.dropped.txt`、VAD |
| **BGM 段出现台词** | 源时间、识别出了什么 | 幻觉过滤、人声分离质量 |

**"语气词太多"有歧义，你要先想清楚想要什么。** 是模型凭空编出来的（BGM 上出现「うん。うん。うん。」），还是真有这些语气词，但你不想在字幕里出现？前者是幻觉问题，后者是你想要一条**新的后处理规则**，两者改的地方完全不同。如果是后者，要明确：删掉还是保留？单独成条还是并入前后句？重复的「うんうんうん」要不要合并成一个？

## 可以直接复制的模板

```
## 问题
一句话：<现象>（例：第 3 分 12 秒附近，字幕比台词晚出现约 0.4 秒）

## 证据
- 样本：ep01__s2_loud_241s.mp4（对应源视频 241～301 秒）
- 产物目录：C:\test\out\baseline\...
- 配置：settings.validate.yaml 原样 / 只改了 vad_threshold=0.35
- 例子（3～5 条，越具体越好）：
  1. cue #47 [00:03:12,400 → 00:03:15,100]
     识别：「…」  实际：「…」
  2. ...
- 范围：个别 / 每 N 条出现一次 / 整段都这样
- 相关输出：SUMMARY 片段、.check.txt 条目、.dropped.txt

## 期望
<字幕应该是什么样>

## 约束
- 先根据日志（grep CHUNK nnn）定位是哪一环节造成的，说明依据，再动手改
- 新行为加配置开关，默认保持旧行为，方便和 baseline 逐项对比
- 一次只处理这一个问题

## 验收
在同一样本上，<指标> 从 X 变为 Y，其他指标不退步
（asr_empty、align_fallback、speech not subtitled）
```

## 填好的例子

```
## 问题
战斗场面里，角色喊叫时识别出大量「あっ」「うっ」「はっ」，单独成条，
但我不需要这些拟声词出现在字幕里。

## 证据
- 样本：ep02__s2_loud_388s.mp4，baseline 配置
- 例子：
  1. cue #31 [00:00:42,100 → 00:00:42,500] 「あっ」（角色被击中的惨叫）
  2. cue #33 [00:00:44,000 → 00:00:44,400] 「はっ！」
  3. cue #35 [00:00:47,800 → 00:00:48,300] 「うっ…」
- 范围：这个片段 14 条里有 9 条是这类，其他片段很少

## 期望
纯拟声词、不含实际词义的短 cue（≤3 个字符）不输出。
但「えっ？」「ああ、そうか」这种有语义的要保留。

## 验收
该样本中纯拟声词 cue 降到 0～2 条，其他 cue 数量不变。
```

## 几个让描述更有效的习惯

- **给 3 到 5 个具体例子，不要写"有些地方不准"。** 一个例子说明不了是个例还是规律，三个以上才能看出共性。
- **附上 cue 序号和 `.srt` 里的时间戳。** Claude Code 能直接 grep 到那一条，再用 `CHUNK nnn` 日志重建它的完整处理路径。
- **量化。** "晚了大约 0.4 秒"比"有点慢"有用，"一分钟里有 9 条"比"很多"有用。
- **同时给出"不要误伤"的反例。** 像上面的「えっ？」，没有反例，改动容易过头。
- **验收标准用 SUMMARY 里已有的指标。** 这样你和 Claude Code 对"改好了"的判断是一致的。
- **一次一个问题。** 把时间轴、识别错误、语气词放进同一个请求，改完很难判断是哪项起了作用。
